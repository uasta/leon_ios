# 13｜Leon 1.0 当前缺口 TODO

## 1. 结论

基于当前仓库代码现状，Leon 1.0 已经有了可运行骨架：

- iOS 已有 `食材 / 推荐 / 我的` 三个主 Tab
- 邮箱注册、登录、登出、当前用户接口已具备
- 推荐流、搜索、详情、点赞、收藏、历史、Tab 顺序偏好已有首版前后端实现
- 本地食材、登录后同步、菜谱缓存、OCR 基础接口已经起步

但离“1.0 可稳定交付”还有明显缺口。

当前更接近：

- `可演示`
- `可联调`
- `未达到完整发布标准`

## 2. 当前最主要的问题

不是完全没功能，而是还存在以下几类问题：

1. 有些能力只有 UI 骨架，还没有形成真接口闭环
2. 有些接口已经存在，但返回仍带占位语义或旧 demo 语义
3. iOS 本地数据模型与后端模型还没有完全对齐
4. 自动化测试覆盖很薄，1.0 主链路几乎没有保护

## 3. 1.0 完整可用目标

这里把“1.0 可以完整使用”先定义清楚。

用户至少应当可以稳定完成下面链路：

1. 注册 / 登录
2. 查看推荐流
3. 搜索菜谱
4. 查看菜谱详情和图片
5. 手动录入食材
6. 管理食材
7. 带着食材去推荐
8. 通过图片 OCR 导入食材
9. 登录后同步食材、点赞、收藏、历史、Tab 顺序

## 6. 建议优先级

如果目标是尽快让 1.0 变成“可以完整使用”，建议先做下面这些：

1. 前端把登录、食材管理、推荐详情、OCR 导入接成完整主流程
2. 后端把食材 CRUD、同步、推荐详情、OCR 候选返回彻底收口
3. 前后端一起清理旧 demo 语义和旧接口文档
4. 给主链路补最小测试保护

## 7. 一句话判断

当前版本已经能演示，但距离“1.0 完整可用”还差三件大事：

- 食材与账号同步闭环
- 菜谱详情与 OCR 的真数据闭环
- 前后端主链路的测试与文档收口
