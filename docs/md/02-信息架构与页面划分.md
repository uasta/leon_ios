# 02｜信息架构与页面划分

目标：让用户先把“我有什么”录进去，再自然过渡到“我能做什么”，最后把个人行为沉淀到“我的”。

## 导航总览

采用 **Tab Bar + NavigationStack + Sheet** 组合。

- **Tab A：食材**
  - 食材列表
  - 食材录入
  - 小票识别结果确认
  - 食材管理
- **Tab B：推荐**
  - 搜索
  - 瀑布流推荐
  - 食谱详情
- **Tab C：我的**
  - 登录
  - 点赞
  - 收藏
  - 历史

## Tab 顺序规则

- 默认顺序：`食材`、`推荐`、`我的`
- `食材` 与 `推荐` 可以互换顺序
- `我的` 固定在最右
- 自定义顺序属于用户偏好，优先本地保存；登录后可同步到账号

## 模块边界

### 1）食材模块

负责“录入、查看、筛选、勾选、管理”。

- 列表浏览
- 单选 / 多选
- 手动录入
- 输入搜索辅助录入
- 小票识别导入
- 删除、编辑、批量处理
- 跳转推荐

### 2）推荐模块

负责“找菜、看菜、承接食材上下文”。

- 关键词搜索菜谱
- 基于已选食材生成推荐结果
- 瀑布流浏览推荐内容
- 查看食谱详情
- 在详情里触发点赞、收藏

### 3）我的模块

负责“账号入口 + 行为沉淀”。

- 登录状态展示
- 点赞记录
- 收藏列表
- 浏览历史

## 核心页面说明

### 1）食材列表（Tab：食材）

- 顶部：搜索入口或快捷录入入口
- 列表主体：已有食材
- 选择态：
  - 支持单选
  - 支持多选
- 主动作：
  - 手动添加
  - 搜索添加
  - 小票识别导入
  - 带着已选食材去推荐

### 2）食材录入（Sheet）

- 录入方式：
  - 手打添加
  - 输入搜索后选择候选
- 表单建议字段：
  1. 名称
  2. 数量 / 单位
  3. 备注

### 3）小票识别结果确认（Sheet / Push）

- 上传或拍摄小票
- 返回候选食材列表
- 用户勾选、修正、确认入库

### 4）推荐列表（Tab：推荐）

- 顶部：搜索
- 内容：瀑布流食谱卡片
- 来源：
  - 默认推荐流
  - 来自食材页的定向推荐结果

### 5）食谱详情（从推荐 push）

- 菜谱基础信息
- 所需食材
- 做法说明
- 点赞 / 收藏

### 6）我的（Tab：我的）

- 未登录：展示登录入口
- 已登录：展示点赞、收藏、历史入口与摘要

## 关键交互约束

- 食材页到推荐页必须是低阻力跳转，不能要求用户重新组织条件
- 推荐页需要能识别“普通浏览”与“基于已选食材进入”两种上下文
- 点赞、收藏、历史的数据归属到“我的”，不要分散到多个设置入口
- “设置”不再作为底部主 Tab，而应收敛到“我的”内部或后续补充页面
