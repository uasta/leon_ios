# 12｜模块-我的

## 1. 模块目标

我的模块负责 Leon 1.0 的账号承接和行为沉淀。

它要解决的是：

1. 用户可以登录
2. 用户可以看到自己的点赞、收藏、历史
3. 用户可以同步自己的 Tab 顺序偏好

## 2. 用户范围

### 1.0 必做

- 登录
- 点赞
- 收藏
- 历史
- Tab 顺序偏好同步

### 1.0 不做

- 会员
- 用户标签
- 口味偏好页
- 社区

## 3. 前端要做什么

### 3.1 页面

- 我的首页
- 登录页
- 点赞列表页
- 收藏列表页
- 历史列表页

### 3.2 状态

至少需要维护：

- `authStatus`
- `currentUser`
- `likes`
- `favorites`
- `history`
- `tabOrder`

### 3.3 交互

- 未登录状态展示登录入口
- 已登录状态展示点赞、收藏、历史入口
- 登录成功后自动同步本地食材
- 支持同步 Tab 顺序偏好

## 4. 后端要做什么

### 4.1 可复用能力

现有可复用：

- `AuthController`
- `UserFavorite`
- `UserSearchHistory` 的部分思路

### 4.2 需要新增的数据表

- `recipe_likes`
- `recipe_histories`
- `user_preferences`

### 4.3 需要提供的接口

- `POST /api/login`
- `POST /api/logout`
- `GET /api/user`
- `POST /api/v1/recipes/{id}/like`
- `POST /api/v1/recipes/{id}/favorite`
- `POST /api/v1/recipes/{id}/history`
- `GET /api/v1/me/likes/recipes`
- `GET /api/v1/me/favorites/recipes`
- `GET /api/v1/me/history/recipes`
- `GET /api/v1/me/preferences`
- `PUT /api/v1/me/preferences`

### 4.4 偏好规则

`tab_order` 必须满足：

- `ingredients` 和 `recommend` 可以互换
- `me` 固定在最后

### 4.5 当前落地约定

- 当前 iOS 端先走邮箱密码登录以对接现有后端
- 用户登录成功后，先同步本地食材，再同步本地 Tab 顺序偏好
- 浏览详情时自动写入历史
- 我的点赞 / 收藏 / 历史列表支持继续跳转食谱详情
- 退出登录时，需要清掉当前账号对推荐列表的点赞 / 收藏状态覆盖

## 5. 依赖关系

这个模块依赖：

- 共通基础模块
- 推荐模块已经提供真实详情入口

说明：

- 没有推荐详情，点赞、收藏、历史就只是空能力

## 6. 实施顺序

建议按下面顺序做：

1. 沿用现有登录能力
2. 整理当前用户接口
3. 先补收藏到 1.0 语义
4. 再补点赞
5. 再补历史
6. 最后补 `tab_order`
7. 前端接入我的首页和行为列表

## 7. 联调顺序

### 第一次

- 登录
- 当前用户

### 第二次

- 收藏
- 收藏列表

### 第三次

- 点赞
- 历史
- Tab 顺序同步

## 8. 验收标准

这个模块完成后，必须满足：

1. 用户能登录并获取当前状态
2. 用户能收藏食谱并在“我的”查看
3. 用户能点赞食谱并在“我的”查看
4. 用户浏览详情后能形成历史
5. 用户调整过的 Tab 顺序可以保存并在登录后同步
