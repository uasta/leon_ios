# 04｜体验与动效原则（极致丝滑）

目标：让用户感觉“像系统自带 App”，而不是网页套壳或安卓味。

## 页面切换（导航与转场）

- **列表 → 详情**：使用系统 push 动画（不要自定义花哨转场）
- **新增/编辑**：用 Sheet（modal），符合 iOS “任务态”
- **筛选/排序**：优先 Sheet；轻量选项可用 `Menu`
- **返回策略**：任何深层页都能自然 back，不要出现“返回到首页”这种断裂

## 列表（List）体验

- **大多数操作用滑动手势**：`swipeActions`（用掉/丢弃/延期）
- **临期置顶**：减少用户寻找成本
- **搜索即时**：输入即过滤（必要时做 150–250ms 防抖）
- **空状态要有下一步**：空页不是结束，而是“添加/导入”

## 表单（新增/编辑）体验

- 字段尽量少，默认值尽量多
- 允许“只填名称就保存”，其他字段可后补（否则会卡住用户）
- 日期选择：
  - 默认建议值（例如常见食材的保质期模板，后续再加）
  - 支持“未知/不提醒”（用户真实需求）

## 动效使用原则（少而准）

- 动效只做两类：
  - **状态变化**：新增/删除/完成（列表插入、删除动画）
  - **层级变化**：push/sheet（系统动画）
- 避免：
  - 全屏大动效、连续弹跳、非系统曲线
  - 过多 skeleton（工具型 App 以即时反馈为主）

## 加载态与错误态（决定“高级感”）

- **加载**：就地加载（列表里进度/占位），不要全屏转圈
- **错误**：用可读文案 + 明确下一步（重试/改用手机号登录）
- **网络弱**：优先保证本地可用；同步失败不阻断核心操作

## 权限弹窗（通知/相册/相机）

- 先解释再弹系统框：  
  - “开启通知后，我们会在食材临期前提醒你”
- 用户拒绝也能继续用；在设置页保留入口
