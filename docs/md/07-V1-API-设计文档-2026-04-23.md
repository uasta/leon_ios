# 07｜V1 API 设计文档（按当前 1.0 规划）

## 1. 文档目标

这份文档只服务当前 V1 用户端，确保产品、iOS、后端围绕同一套页面和数据结构工作。

## 2. V1 产品范围

V1 主导航为：

- `食材`
- `推荐`
- `我的`

对应核心能力：

- 食材：勾选单个 / 多个食材、跳转推荐、手动录入、输入搜索、小票识别、列表管理
- 推荐：搜索、瀑布流推荐食谱、食谱详情
- 我的：登录、点赞、收藏、历史

## 3. V1 必做与不做

### 3.1 V1 必做

- 登录 / 登出 / 当前用户
- 食材 CRUD
- 食材搜索建议
- 小票 OCR 候选结果返回
- 基于食材的推荐流
- 菜谱搜索
- 菜谱详情
- 点赞 / 收藏 / 历史
- Tab 顺序偏好同步

### 3.2 V1 不做

- 拍照识别食材并打框
- 口味偏好
- 用户标签
- 语音
- 会员
- 社区

## 4. 设计原则

### 4.1 登录是入口，不是门禁

- 用户可以先录食材、看推荐
- 登录主要承接“我的”中的行为同步和偏好同步
- 1.0 不给未登录用户创建服务端临时账号
- 未登录阶段的食材数据默认只存在本地

### 4.2 推荐在 V1 就是主能力

- 推荐接口不是远期预留，而是当前主链路接口
- 早期允许推荐策略简单，但页面与数据结构必须稳定

### 4.3 小票识别只返回候选，不直接入库

- OCR 结果需要用户确认
- 真正写入食材仍走标准食材接口或批量写入接口

## 5. 统一返回格式

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

约定：

- `code = 0` 表示成功
- 参数错误使用 `422`
- 未登录使用 `401`
- 无权限使用 `403`
- 资源不存在使用 `404`

## 6. 核心资源模型

### 6.1 Ingredient

```json
{
  "id": "ing_123",
  "name": "番茄",
  "quantity": "4",
  "unit": "个",
  "note": "适合先用",
  "created_at": "2026-05-08T08:30:00Z",
  "updated_at": "2026-05-08T08:30:00Z"
}
```

### 6.2 RecipeSummary

```json
{
  "id": "recipe_001",
  "title": "番茄炒蛋",
  "cover_url": "https://example.com/recipe_001.jpg",
  "match_reason": "匹配你勾选的番茄和鸡蛋",
  "liked": false,
  "favorited": true
}
```

### 6.3 RecipeDetail

```json
{
  "id": "recipe_001",
  "title": "番茄炒蛋",
  "cover_url": "https://example.com/recipe_001.jpg",
  "ingredients": ["番茄", "鸡蛋", "盐"],
  "steps": ["番茄切块", "鸡蛋打散", "下锅翻炒"],
  "liked": false,
  "favorited": true
}
```

### 6.4 ReceiptOCRCandidate

```json
{
  "name": "鸡蛋",
  "quantity_text": "1盒",
  "confidence": 0.92
}
```

### 6.5 UserPreference

```json
{
  "tab_order": ["ingredients", "recommend", "me"]
}
```

规则：

- 只允许 `ingredients` 和 `recommend` 交换
- `me` 固定在最后

## 7. 页面到 API 的映射

| 页面 | 读取接口 | 写入接口 |
| --- | --- | --- |
| 本地食材列表（未登录） | 本地 Store | 本地 Store |
| 登录后食材列表 | `GET /api/v1/ingredients` | `POST /api/v1/ingredients` |
| 登录后食材编辑 | `GET /api/v1/ingredients/{id}` | `PATCH /api/v1/ingredients/{id}` |
| 登录后食材批量入库 | 无额外读取 | `POST /api/v1/ingredients/bulk` |
| 食材搜索辅助录入 | `GET /api/v1/ingredients/suggestions` | 无 |
| 小票识别 | 无 | `POST /api/v1/ingredients/import/receipt-ocr` |
| 推荐流 | `GET /api/v1/recommendations/feed` | 无 |
| 基于食材去推荐 | 无 | `POST /api/v1/recommendations/by-ingredients` |
| 菜谱搜索 | `GET /api/v1/recipes/search` | 无 |
| 食谱详情 | `GET /api/v1/recipes/{id}` | `POST /api/v1/recipes/{id}/like` `POST /api/v1/recipes/{id}/favorite` `POST /api/v1/recipes/{id}/history` |
| 我的-点赞 | `GET /api/v1/me/likes/recipes` | 无 |
| 我的-收藏 | `GET /api/v1/me/favorites/recipes` | 无 |
| 我的-历史 | `GET /api/v1/me/history/recipes` | 无 |
| 我的-导航偏好 | `GET /api/v1/me/preferences` | `PUT /api/v1/me/preferences` |
| 登录后本地食材上云 | 无 | `POST /api/v1/sync/bootstrap` |
| 登录状态 | `GET /api/user` | `POST /api/login` `POST /api/logout` |

## 8. API 清单

## 8.1 认证接口

### 8.1.1 登录

`POST /api/login`

### 8.1.2 登出

`POST /api/logout`

### 8.1.3 当前用户

`GET /api/user`

## 8.2 食材接口

### 8.2.1 获取食材列表（登录后）

`GET /api/v1/ingredients`

查询参数：

- `keyword`：按名称搜索
- `page`
- `per_page`

### 8.2.2 创建食材（登录后）

`POST /api/v1/ingredients`

请求体：

```json
{
  "name": "番茄",
  "quantity": "4",
  "unit": "个",
  "note": "先吃"
}
```

### 8.2.3 获取食材详情（登录后）

`GET /api/v1/ingredients/{id}`

### 8.2.4 编辑食材（登录后）

`PATCH /api/v1/ingredients/{id}`

### 8.2.5 删除食材（登录后）

`DELETE /api/v1/ingredients/{id}`

### 8.2.6 批量创建食材（登录后）

`POST /api/v1/ingredients/bulk`

请求体：

```json
{
  "items": [
    {
      "name": "鸡蛋",
      "quantity": "1",
      "unit": "盒"
    },
    {
      "name": "牛奶",
      "quantity": "1",
      "unit": "瓶"
    }
  ]
}
```

### 8.2.7 食材搜索建议

`GET /api/v1/ingredients/suggestions`

查询参数：

- `keyword`

返回建议用于手动录入时的输入搜索。

### 8.2.8 小票 OCR

`POST /api/v1/ingredients/import/receipt-ocr`

请求体：

- `multipart/form-data`
- `image`

响应示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "candidates": [
      {
        "name": "鸡蛋",
        "quantity_text": "1盒",
        "confidence": 0.92
      }
    ]
  }
}
```

## 8.3 推荐与菜谱接口

### 8.3.1 推荐流

`GET /api/v1/recommendations/feed`

查询参数：

- `page`
- `per_page`

说明：

- 返回默认推荐流

### 8.3.2 基于食材去推荐

`POST /api/v1/recommendations/by-ingredients`

请求体：

```json
{
  "ingredients": ["番茄", "鸡蛋", "土豆"]
}
```

说明：

- 这个接口用于未登录阶段
- 客户端直接把本地食材名数组传给后端
- 不依赖服务端食材 ID

### 8.3.3 菜谱搜索

`GET /api/v1/recipes/search`

查询参数：

- `q`
- `page`
- `per_page`

返回结构约定：

- `query`
- `recipes`
- `total`

其中 `recipes[*]` 至少包含：

- `id`
- `title`
- `cover_url`
- `match_reason`
- `liked`
- `favorited`

### 8.3.4 菜谱详情

`GET /api/v1/recipes/{id}`

返回结构约定：

- `id`
- `title`
- `cover_url`
- `ingredients`
- `steps`
- `liked`
- `favorited`

## 8.4 我的模块接口

### 8.4.1 点赞菜谱

`POST /api/v1/recipes/{id}/like`

请求体：

```json
{
  "liked": true
}
```

### 8.4.2 收藏菜谱

`POST /api/v1/recipes/{id}/favorite`

请求体：

```json
{
  "favorited": true
}
```

### 8.4.3 我的点赞

`GET /api/v1/me/likes/recipes`

### 8.4.4 我的收藏

`GET /api/v1/me/favorites/recipes`

### 8.4.5 我的历史

`GET /api/v1/me/history/recipes`

说明：

- 历史可由用户查看菜谱详情时自动写入
- 当前 1.0 使用：
  - `POST /api/v1/recipes/{id}/history`

### 8.4.6 我的偏好

`GET /api/v1/me/preferences`

`PUT /api/v1/me/preferences`

请求体：

```json
{
  "tab_order": ["recommend", "ingredients", "me"]
}
```

服务端校验：

- `recommend` 和 `ingredients` 允许互换
- `me` 必须排在最后

## 9. 客户端状态建议

客户端至少维护：

- `authStatus`
- `selectedIngredientNames`
- `ingredients`
- `recommendationFeed`
- `likes`
- `favorites`
- `history`
- `tabOrder`

说明：

- `selectedIngredientNames` 用于食材页到推荐页的上下文传递
- `tabOrder` 先本地生效，登录后再同步

## 9.1 本地食材上云

### 9.1.1 登录后同步本地食材

`POST /api/v1/sync/bootstrap`

请求体：

```json
{
  "ingredients": [
    {
      "name": "番茄",
      "quantity": "4",
      "unit": "个",
      "note": ""
    }
  ]
}
```

说明：

- 这个接口只在用户登录后触发
- 作用是把匿名阶段的本地食材一次性迁移到账号

## 10. V2 预留接口方向

V2 再考虑新增：

- `POST /api/v2/ingredients/detect`
  - 上传食材照片
  - 返回识别框与食材标签
- `GET /api/v2/me/taste-profile`
- `PUT /api/v2/me/taste-profile`
- `GET /api/v2/me/tags`
- `PUT /api/v2/me/tags`

## 11. 服务端实现顺序

建议按下面顺序推进：

1. 认证接口沿用现有能力
2. 起食材接口
3. 起推荐流、菜谱搜索、菜谱详情
4. 起点赞、收藏、历史
5. 起偏好接口
6. 最后起小票 OCR

## 12. 结论

V1 API 的核心不是“做一个大而全的厨房平台”，而是稳定支持三条主链路：

1. 录入食材
2. 基于食材看推荐
3. 在“我的”里沉淀登录与行为
