# 11｜模块-推荐

## 1. 模块目标

推荐模块是 Leon 1.0 的第二核心。

它要解决的是：

1. 用户能主动搜菜
2. 用户能基于已有食材看推荐
3. 用户能进入食谱详情

## 2. 用户范围

### 1.0 必做

- 推荐流
- 搜索菜谱
- 瀑布流展示
- 食谱详情
- 承接食材模块带来的本地食材上下文

### 1.0 不做

- 复杂个性化推荐
- 口味画像驱动推荐
- 动态 AI 生成菜谱

## 3. 前端要做什么

### 3.1 页面

- 推荐首页
- 搜索结果页
- 食谱详情页

### 3.2 状态

至少需要维护：

- `recommendationFeed`
- `recommendationQuery`
- `selectedIngredientNames`
- `recipeDetail`
- `recommendationLoadingState`

### 3.3 交互

- 默认推荐流
- 支持搜索
- 支持瀑布流加载
- 支持“来自食材页”的上下文推荐
- 支持进入详情页

## 4. 后端要做什么

### 4.1 可复用能力

现有 `RecipeController` 中可复用：

- 搜索
- 搜索建议
- 热门搜索
- 外部算法服务调用基础

### 4.2 需要补齐的接口

- `GET /api/v1/recommendations/feed`
- `GET /api/v1/recipes/search`
- `GET /api/v1/recipes/{id}`
- `POST /api/v1/recommendations/by-ingredients`

### 4.3 推荐流原则

- 不传食材上下文时，返回普通推荐流
- 传入食材名数组时，返回基于当前已选食材的推荐结果

### 4.4 详情数据

食谱详情至少返回：

- `id`
- `title`
- `cover_url`
- `ingredients`
- `steps`
- `liked`
- `favorited`

### 4.5 1.0 当前落地约定

- `GET /api/v1/recipes/search` 返回轻量摘要结构，前端不直接消费算法原始字段
- `GET /api/v1/recipes/{id}` 优先读服务端缓存，不够时先返回可展示的占位详情
- 推荐首页同时承担默认推荐流和搜索结果承接
- 详情页的点赞 / 收藏操作需要把状态即时回流到推荐列表和“我的”
- 登录恢复后，需要把账号已有的点赞 / 收藏状态重新回填到推荐卡片

## 5. 依赖关系

这个模块依赖：

- 共通基础模块
- 食材模块的 `selectedIngredientNames`

这个模块会输出给我的模块：

- 收藏来源
- 点赞来源
- 历史来源

## 6. 实施顺序

建议按下面顺序做：

1. 整理现有 `RecipeController` 返回结构
2. 先起 `feed` 接口
3. 再整理 `search` 接口到 1.0 语义
4. 起 `by-ingredients` 接口
5. 新增详情接口
6. 前端接推荐流
7. 前端接搜索
8. 前端接“食材上下文推荐”
9. 前端接详情页

## 7. 联调顺序

### 第一次

- 推荐流
- 瀑布流 UI

### 第二次

- 搜索
- 搜索结果展示

### 第三次

- 食材页跳推荐页
- `selectedIngredientNames` 传递
- 详情页数据

## 8. 验收标准

这个模块完成后，必须满足：

1. 用户不登录也能看推荐流
2. 用户不登录也能搜索菜谱
3. 用户从食材页带入的本地食材上下文能作用到推荐结果
4. 用户能进入食谱详情
5. 推荐模块能为“我的”提供点赞、收藏、历史的真实入口
