# 10｜模块-食材

## 1. 模块目标

食材模块是 Leon 1.0 的起点。

它要解决的是：

1. 用户能把食材快速录进去
2. 用户能管理已有食材
3. 用户能把选中的食材带到推荐模块

## 2. 用户范围

### 1.0 必做

- 食材列表
- 单选 / 多选
- 手动录入
- 输入搜索辅助录入
- 小票识别导入
- 删除 / 编辑
- 从食材跳转推荐

### 1.0 不做

- 拍照识别食材打框
- 复杂食材分类体系
- 智能过期判断模型

## 3. 前端要做什么

### 3.1 页面

- 食材首页
- 食材新增 / 编辑页
- 小票识别结果确认页

### 3.2 状态

至少需要维护：

- `ingredients`
- `selectedIngredientNames`
- `ingredientSuggestions`
- `receiptCandidates`
- `ingredientLoadingState`

### 3.3 交互

- 支持单选
- 支持多选
- 支持“带着已选食材去推荐”
- 支持手动添加
- 支持搜索候选添加
- 支持 OCR 结果勾选后批量入库

## 4. 后端要做什么

### 4.1 数据表

建议新增：

- `ingredients`

建议字段：

- `id`
- `user_id`
- `name`
- `quantity`
- `unit`
- `note`
- `created_at`
- `updated_at`

说明：

- 1.0 先不要把字段做太重
- 只保留当前前端真实需要的最小集
- 这个表服务的是登录后的正式账号食材

### 4.2 接口

登录后必须提供：

- `GET /api/v1/ingredients`
- `POST /api/v1/ingredients`
- `GET /api/v1/ingredients/{id}`
- `PATCH /api/v1/ingredients/{id}`
- `DELETE /api/v1/ingredients/{id}`
- `POST /api/v1/ingredients/bulk`

匿名和登录都可提供：

- `GET /api/v1/ingredients/suggestions`
- `POST /api/v1/ingredients/import/receipt-ocr`
- `POST /api/v1/recommendations/by-ingredients`
- `POST /api/v1/sync/bootstrap`

### 4.3 OCR 处理原则

- OCR 只返回候选结果
- 不直接写入食材表
- 未登录时：确认结果后先写入本地食材
- 登录后：再由同步接口统一上云

### 4.4 1.0 匿名方案

- 未登录时，食材 CRUD 只在本地进行
- 本地食材需要持久化保存，避免用户下次打开丢失
- 不给未登录用户创建服务端临时用户
- 从食材跳推荐时，客户端直接把食材名数组传给推荐接口
- 登录后，再通过 `POST /api/v1/sync/bootstrap` 把本地食材同步到账号

## 5. 依赖关系

这个模块依赖：

- 共通基础模块已完成

这个模块会输出给推荐模块：

- `selectedIngredientNames`
- 食材名称和基础信息

## 6. 实施顺序

建议按下面顺序做：

1. 先起 `ingredients` migration / model / controller
2. 起登录后食材列表、创建、编辑、删除
3. 起 `bulk` 接口
4. 起 `suggestions` 接口
5. 起 `sync/bootstrap`
6. 改造 OCR 为 1.0 语义
7. 前端先保持本地食材列表和新增编辑
8. 前端接多选和跳转推荐
9. 前端接 OCR 结果确认与本地入库
10. 登录后再接食材上云

## 7. 联调顺序

联调建议分三次做：

### 第一次

- 本地食材列表
- 本地食材新增
- 本地食材编辑
- 本地食材删除

### 第二次

- 食材多选
- 带食材去推荐
- `selectedIngredientNames` 传递

### 第三次

- OCR 上传
- 候选结果返回
- 本地批量入库
- 登录后同步上云

## 8. 验收标准

这个模块完成后，必须满足：

1. 用户不登录也能录入食材
2. 用户不登录也能看到食材列表
3. 用户能选中一个或多个食材
4. 用户能从食材页跳到推荐页
5. 小票识别结果可以确认后批量入库
6. 用户登录后可以把本地食材同步到账号
