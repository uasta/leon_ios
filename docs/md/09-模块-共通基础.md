# 09｜模块-共通基础

## 1. 模块目标

这个模块不直接对应某个 Tab，但它是 Leon 1.0 后面所有模块的共同底座。

如果这部分不先定好，后面食材、推荐、我的都会在联调时反复返工。

## 2. 本模块范围

### 前端

- App 主导航结构
- Tab 顺序本地状态
- 网络层
- 统一错误处理
- 统一 loading / empty / error 状态
- 认证状态管理
- Mock 和真实 API 切换方式
- 匿名本地数据与登录后上云的边界

### 后端

- 统一 API 返回格式
- `/api/v1` 路由组
- 统一鉴权策略
- 统一异常返回
- 环境变量与第三方服务配置
- OpenAPI 重写基线
- 登录后本地数据迁移入口

## 3. 前端需要落实的内容

### 3.1 主导航结构

- 底部 Tab 固定为：
  - `食材`
  - `推荐`
  - `我的`
- `食材` 与 `推荐` 可以交换顺序
- `我的` 固定在最后

### 3.2 Store 拆分

建议至少拆为：

- `SessionStore`
- `PreferenceStore`
- `IngredientStore`
- `RecommendationStore`
- `ProfileStore`

其中：

- `IngredientStore` 负责匿名阶段的本地食材持久化
- 登录后通过 `sync/bootstrap` 把本地食材迁移到账号

### 3.3 服务层

建议新增或整理：

- `APIClient`
- `AuthService`
- `IngredientService`
- `RecommendationService`
- `ProfileService`

### 3.4 通用状态

所有模块统一使用：

- `idle`
- `loading`
- `success`
- `empty`
- `error`

## 4. 后端需要落实的内容

### 4.1 统一返回格式

建议统一为：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

### 4.2 路由分层

建议保留：

- `/api/login`
- `/api/logout`
- `/api/user`

建议新增：

- `/api/v1/...`

### 4.3 鉴权边界

未登录可用：

- 本地食材录入
- 本地食材列表
- 推荐搜索
- 推荐流
- 基于本地食材去推荐
- 小票识别

登录后使用：

- 云端食材 CRUD
- 本地食材上云
- 点赞
- 收藏
- 历史
- Tab 顺序同步

补充原则：

- 1.0 不给未登录用户创建服务端临时账号
- 未登录阶段的食材数据只保存在本地
- 登录后通过同步接口把本地食材迁移到正式账号

### 4.4 第三方服务配置

后端必须显式管理：

- `ALGORITHM_HOST`
- `ALGORITHM_PORT`
- `OCR_PORT`
- `FILESYSTEM_DISK`

## 5. 前后端对齐项

这一模块必须先对齐下面几件事：

1. 成功和错误响应格式
2. 分页字段命名
3. 鉴权失败返回
4. 匿名与登录态边界
5. `tab_order` 数据结构
6. 本地食材与云端食材的迁移时机

## 6. 交付物

前端交付物：

- 主 Tab 骨架
- Store 骨架
- Service 骨架
- 通用请求封装

后端交付物：

- `/api/v1` 路由组
- 统一 response helper 或统一返回约定
- OpenAPI 1.0 基线
- 环境变量说明
- `sync/bootstrap` 设计

### 6.1 本地联调基线

这一模块还需要明确最小可运行方式：

- `php_admin` 默认使用 SQLite 本地联调
- iOS 默认基础地址为 `http://localhost:8000`
- 模拟器可直接使用 `localhost`
- 真机调试需要改成电脑局域网 IP

当前已确定：

- 不为匿名用户创建后端临时账号
- 匿名食材只存在 iOS 本地
- 登录后再调用 `POST /api/v1/sync/bootstrap` 做正式账号同步
- 推荐相关接口需要支持“无算法服务时的本地缓存兜底”

后端第一次启动建议执行：

```bash
cd /Users/huliang/Downloads/work/leon/leon_phone/php_admin
chmod -R u+w storage bootstrap/cache database
chmod u+w database/database.sqlite
php artisan migrate --force
php artisan db:seed --force
php artisan serve
```

## 7. 验收标准

满足下面条件即可进入下一个模块：

1. 前端已能切换 mock / real API
2. 后端已明确 1.0 接口命名规则
3. 登录态和匿名态边界已定
4. Tab 顺序结构已定
5. 匿名阶段的食材本地优先方案已定
6. 不再继续沿用 `tasks demo` 作为主要接口语义
