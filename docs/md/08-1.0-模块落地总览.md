# 08｜Leon 1.0 模块落地总览

## 1. 文档目标

从现在开始，Leon 1.0 不再按“前端一份、后端一份”分开推进，而是按模块推进。

每个模块都同时包含：

- 产品边界
- 前端实现范围
- 后端实现范围
- 接口与数据
- 联调顺序
- 验收标准

目标是让我们后面能按模块一个一个落地，而不是前后端各自推进后再拼接。

## 2. 1.0 模块拆分

Leon 1.0 建议拆成 4 个模块：

1. 共通基础
2. 食材
3. 推荐
4. 我的

说明：

- `共通基础` 不是用户直接感知的 Tab，但它决定了后面三个模块能不能稳定接上
- `食材` 是 1.0 起点
- `推荐` 是 1.0 的第二核心
- `我的` 是 1.0 的行为沉淀模块

## 3. 推荐实施顺序

建议严格按下面顺序推进：

1. 共通基础
2. 食材
3. 推荐
4. 我的

原因：

- 没有基础规范，后面模块会反复返工
- 没有食材，推荐失去上下文
- 没有推荐，我的中的收藏和历史没有真实来源

## 4. 各模块对应文档

- `09-模块-共通基础.md`
- `10-模块-食材.md`
- `11-模块-推荐.md`
- `12-模块-我的.md`

## 5. 模块推进方法

每个模块统一按下面顺序做：

1. 先确认范围，不加额外需求
2. 先确定数据结构和接口
3. 后端起 migration / model / route / controller
4. 前端起 store / service / page / state
5. 先 mock 自测，再真接口联调
6. 通过模块验收后再进入下一模块

## 6. 当前版本边界

1.0 必做：

- 食材录入与管理
- 基于食材进入推荐
- 推荐搜索、瀑布流、详情
- 登录、点赞、收藏、历史
- 小票识别

2.0 再做：

- 拍照识别食材
- 识别打框
- 口味偏好
- 用户标签

## 7. 当前项目分工原则

因为前后端都由我们自己实现，所以每个模块都要遵守同一个推进原则：

- 不先卷 UI 细节，再补业务
- 不先写后端很多接口，再反推页面
- 不把远期 2.0 能力混入 1.0 模块

正确顺序是：

1. 先定模块边界
2. 再定前后端最小闭环
3. 再开始实现

## 8. 模块完成定义

一个模块只有同时满足下面条件，才算完成：

1. 页面主流程能走通
2. 前端状态结构稳定
3. 后端接口结构稳定
4. 真接口联调通过
5. 有明确验收结论
